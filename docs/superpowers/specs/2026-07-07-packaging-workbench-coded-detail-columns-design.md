# 包装工作台有码料明细字段调整设计

## 背景

当前包装工作台在 `包装中` 页签下，有码料展开明细使用的是：

- 多选
- 序号
- 二维码编号
- 定长(mm)

现场希望这一块改成和示意图一致的展示方式，更贴近实际装托操作时对长支信息的识别习惯。

## 目标

- 将有码料展开明细改成与图片一致的字段结构。
- 保留左侧多选能力，继续支撑已有“先选短支再装托”的流程。
- 仅调整展示字段，不改动装托、勾选、扣减等业务逻辑。

## 范围

### 纳入本次改造

- `src/views/extrusion/PackagingWorkbench.vue`

### 不在本次范围

- 不修改右上角 `装托` 入口。
- 不修改有码料/无码料装托逻辑。
- 不修改弹窗字段和装托提交逻辑。
- 不修改无码料展示结构。

## 方案

### 1. 有码料明细字段改成图片同款

- 左侧保留多选框。
- 保留 `序号` 列。
- 将 `二维码编号` 改为 `长支码`。
- 将 `定长(mm)` 改为 `长支长度`。
- 新增 `挤压批次` 列。

最终列顺序为：

- 多选
- 序号
- 长支码
- 长支长度
- 挤压批次

### 2. 字段映射规则

- `长支码`：使用当前明细的 `details.code`
- `长支长度`：使用当前明细的 `details.fixedLength`
- `挤压批次`：使用当前主表行的 `row.batchNo`

### 3. 保持现有交互不变

- 有码料仍然通过展开明细勾选短支。
- 勾选状态仍由现有 `selection-change` 逻辑维护。
- 右上角 `装托` 的前置校验和弹窗流程保持不变。

## 风险与控制

- 风险：字段名称变化后，现场可能误以为数据来源也变化。
- 控制：仅调整列名与展示映射，不修改底层数据结构和业务逻辑。

- 风险：新增 `挤压批次` 后列宽不足，影响长支码显示。
- 控制：保留 `长支码` 的较大宽度，并为超长内容继续使用 `show-overflow-tooltip`。

## 验证

- `包装中` 页签下，有码料展开明细显示为“多选、序号、长支码、长支长度、挤压批次”。
- `长支码` 显示当前长码字符串，并支持超长省略悬浮查看。
- `长支长度` 正确显示明细 `fixedLength`。
- `挤压批次` 正确显示主表 `batchNo`。
- 多选短支后，右上角 `装托` 流程仍可正常使用。
- `npm run build` 通过。
