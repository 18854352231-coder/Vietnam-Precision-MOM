# 全系统表格列宽统一优化设计

## 背景

当前越南 MOM 系统中各模块表格列宽配置风格不统一，存在以下常见问题：

- 长文本字段宽度偏窄，出现大量截断或拥挤。
- 短字段宽度偏宽，浪费横向空间。
- 不同模块对同类字段的宽度设置差异较大，页面观感不一致。
- 操作列、时间列、数量列缺少统一的宽度策略。

本次改造按“保守型全量治理”推进，在不改业务逻辑的前提下，对全系统主要表格页做统一列宽优化。

## 目标

- 一次性优化全系统主要表格页面的列宽表现。
- 保持字段、业务流程、按钮行为、接口逻辑不变。
- 统一长字段、短字段、时间字段、数量字段、操作列的宽度策略。
- 对明显易溢出的长文本字段补充 `show-overflow-tooltip`。

- 不抽离公共表格组件或重构列配置结构。
- 不追求每个页面做完全独立的深度定制排版。

## 方案

### 统一宽度规则

#### 长字段

适用字段：

- `名称`
- `订单号`
- `批次号`
- `客户名称`
- `产品号`
- `产品名称`
- `模具号`
- `规格`
- `备注`

策略：

- 优先放宽到 `140-180` 区间。
- 视字段典型长度补充 `show-overflow-tooltip`。

#### 短字段

适用字段：

- `代码`
- `状态`
- `班组`
- `机台`
- `牌号`
- `来源`
- `类型`

策略：

- 控制在 `80-110` 区间。
- 状态列优先居中。

#### 时间字段

适用字段：

- `时间`
- `日期`
- `创建时间`
- `完工时间`
- `检测时间`

策略：

- 统一使用 `140-170` 区间。

#### 数量和重量字段

适用字段：

- `数量`
- `支数`
- `重量`
- `净重`
- `毛重`
- `长度`

策略：

- 宽度优先控制在 `80-110` 区间。
- 保持数值列右对齐。

#### 操作列

策略：

- 保持较宽宽度，避免按钮换行。
- 一般控制在 `220-320` 区间，按页面操作按钮数量微调。

### 页面处理方式

- 优先调整高频主表，不深度重排复杂弹窗子表。
- 对单页内多个表格，仅修正明显不合理的列宽。
- 对已经较合理的页面仅做轻量统一，不做过度改动。

### tooltip 策略

以下场景优先增加 `show-overflow-tooltip`：

- 长编号字段。
- 名称类字段。
- 备注类字段。
- 报表页中的长文本列。

## 风险与控制

- 风险：一次修改文件较多，可能出现局部列宽不理想或遗漏。
- 控制：采用“保守型治理”，以统一规则为主，不做大幅结构调整。
- 风险：多表页面若重排过多，可能影响既有操作习惯。
- 控制：不大改列顺序，只对明显高频字段做轻量前置。
- 风险：批量修改后可能出现模板语法或类型问题。
- 控制：完成后统一执行诊断和构建验证。

## 验证

- 操作列按钮不换行。
- 长文本字段悬停可查看完整内容。
- `npm run build` 通过。
