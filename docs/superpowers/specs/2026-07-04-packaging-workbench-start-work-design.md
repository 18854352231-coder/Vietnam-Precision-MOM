# 包装工作台“开工 / 批量开工”设计

## 背景

当前包装工作台已经按状态拆成了 `待包装`、`包装中`、`已完工`、`报废列表` 四个页签，但 `待包装` 列表的开工入口需要同时支持单条开工和批量开工，且入口位置要与页面操作习惯保持一致。

## 目标

- 在操作列提供单条 `开工` 按钮。
- 支持勾选多条 `待包装` 数据后批量开工。
- 点击单条 `开工` 或 `批量开工` 后，将目标数据的状态更新为 `包装中`。
- 状态变更后，数据自动从 `待包装` 页签消失，并在 `包装中` 页签可见。

## 范围

### 纳入本次改造

- `src/views/extrusion/PackagingWorkbench.vue`

### 不在本次范围

- 不新增“开工人”或“开工时间”字段。
- 不增加二次确认弹窗。
- 不修改“装托”“打印”“报废”既有业务流程。
- 不改后端接口，仅调整当前前端页面的本地状态流转。

## 方案

### 按钮位置

- 在 `待包装` 页签的操作区显示 `批量开工` 按钮。
- 当没有勾选任何数据时，`批量开工` 按钮置灰不可用。
- 切换到其他页签时，不显示 `批量开工` 按钮。
- 在表格操作列中增加单条 `开工` 按钮。
- 单条 `开工` 仅对 `待包装` 行显示。
- `装托` 仅对 `包装中` 行显示。

### 开工规则

- 单条 `开工` 仅处理当前点击行。
- `批量开工` 仅处理当前勾选的数据。
- 两种入口都仅将状态为 `待包装` 的数据更新为 `包装中`。
- 已经处于其他状态的数据不做额外处理。

### 状态流转结果

- 开工成功后，列表数据中的 `status` 更新为 `包装中`。
- 当前页签为 `待包装`，因此这些数据会立即从当前表格中消失。
- 用户切到 `包装中` 页签后，可看到刚刚开工的数据。

## 交互反馈

- 单条 `开工` 成功后，提示“已开工 1 条数据”。
- `批量开工` 成功后，提示“已开工 X 条数据”。
- 批量操作完成后清空当前勾选项，避免误操作。

## 风险与控制

- 风险：用户误选多条数据后直接开工。
- 控制：本次按用户确认的 A 方案执行，不加确认弹窗；通过成功提示和勾选清空降低误操作持续影响。

## 验证

- 在 `待包装` 页签点击某一行的 `开工`，该条数据进入 `包装中`。
- 在 `待包装` 页签勾选多条数据后点击 `批量开工`，多条数据一起进入 `包装中`。
- 切换到 `包装中` 页签后可以看到刚开工的数据。
- `npm run build` 通过。
