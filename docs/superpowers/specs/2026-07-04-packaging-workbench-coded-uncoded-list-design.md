# 包装工作台有码料/无码料列表展示设计

## 背景

当前包装工作台列表是单层主表，只按料框汇总展示，未区分 `有码料` 与 `无码料`。

业务上存在两类料框：

- `有码料`：需要查看该料框下的明细记录
- `无码料`：无需查看逐条明细，只需要看到汇总数量

因此需要在包装工作台列表中引入 `有码料/无码料` 区分，并为有码料提供明细展开能力。

## 目标

- 在包装工作台主列表中区分 `有码料` 与 `无码料`
- `有码料` 支持展开查看料框明细
- `无码料` 不展开，仅在主表显示数量
- 保持现有页签、开工、装托、来料报废、打印预览等流程不变

## 范围

### 纳入本次改造

- `src/views/extrusion/PackagingWorkbench.vue`
- 包装工作台主列表展示结构
- mock 数据结构扩展

### 不在本次范围

- 不修改 `开工 / 批量开工` 流程
- 不修改 `装托` 弹窗与提交流程
- 不修改 `来料报废` 逻辑
- 不修改 `打印预览` 逻辑
- 不修改顶部搜索逻辑
- 不接入后端接口，仅调整当前前端展示与 mock 数据

## 方案

### 主表结构

包装工作台主表新增 `料框类型` 列，用于明确区分两种料框：

- `有码料`
- `无码料`

内部数据字段建议使用：

- `isCoded: boolean`

字段口径：

- `isCoded: true` 表示有码料
- `isCoded: false` 表示无码料

### 展开交互

主表新增展开行能力，但仅对 `有码料` 生效。

- `有码料`：显示展开入口，展开后展示该料框的明细子表
- `无码料`：不显示展开内容，仅在主表显示数量

为避免无码料出现无意义的空展开区域，无码料行应禁止展开或隐藏展开能力。

### 明细数据结构

每条主表数据补充：

- `details: []`

字段口径：

- `有码料`：`details` 为明细数组，主表数量为明细数量汇总
- `无码料`：`details` 为空数组，主表数量直接取汇总值

### 有码料明细子表字段

有码料展开后的子表先展示以下字段：

- `序号`
- `条码/标识码`
- `产品号`
- `长度`
- `数量`
- `状态`

本次只做静态展示，不在明细表内增加编辑、删除、打印等操作。

## 数据示例

### 有码料

```ts
{
  frameNo: 'F-2605001',
  qty: 100,
  isCoded: true,
  details: [
    { id: 1, code: 'BC-001', productNo: 'P-1001', length: '6.0', qty: 20, status: '待包装' },
    { id: 2, code: 'BC-002', productNo: 'P-1001', length: '6.0', qty: 30, status: '待包装' },
    { id: 3, code: 'BC-003', productNo: 'P-1001', length: '6.0', qty: 50, status: '待包装' }
  ]
}
```

### 无码料

```ts
{
  frameNo: 'F-2605002',
  qty: 120,
  isCoded: false,
  details: []
}
```

## 实现边界

本次先完成“列表识别与展示分流”，不扩展到包装流程差异化处理。

也就是说：

- `有码料` 与 `无码料` 的差异仅体现在列表展示层
- 后续若需要区分装托、打印、追溯流程，可在此结构基础上继续扩展

## 风险与控制

- 风险：当前包装工作台无现成明细结构
- 控制：先通过 mock 数据补充 `isCoded` 与 `details`，仅做前端展示

- 风险：展开列对无码料产生空白交互
- 控制：为无码料禁用展开，避免无效操作

- 风险：主表数量与明细数量不一致
- 控制：mock 数据中保证有码料 `qty` 与 `details` 汇总一致

## 验证

- 主表新增 `料框类型` 列
- `有码料` 行可展开并显示明细子表
- `无码料` 行不展开，仅显示数量
- 主表 `qty` 显示正常
- 页签切换、开工、装托、来料报废、打印预览不受影响
- `npm run build` 通过
