# 包装工作台包装中测试数据补充设计

## 背景

当前包装工作台的 Mock 数据中，`包装中` 状态只有 `1` 条无码料样例，缺少有码料的 `包装中` 数据，不利于验证最新的装托流程：

- 有码料：需要先勾选短支再装托
- 无码料：不需要勾选短支，直接输入数量装托

## 目标

- 在 `包装中` 列表中补充可直接用于测试的 Mock 数据。
- 同时覆盖有码料和无码料两种装托场景。
- 仅补数据，不改动页面交互和业务逻辑。

## 范围

### 纳入本次改造

- `src/views/extrusion/PackagingWorkbench.vue`

### 不在本次范围

- 不修改装托、报废、开工逻辑。
- 不修改列表字段、弹窗布局和校验逻辑。
- 不接入后端接口，仅调整前端 Mock 数据。

## 方案

### 1. 保留现有包装中无码料数据

- 保留当前已有的 `id: 2` 这条 `包装中` 无码料数据不动。

### 2. 新增有码料包装中样例

- 新增 `2` 条 `包装中` 状态的有码料数据。
- 每条数据都带 `details` 明细，满足短支勾选装托测试。
- 明细中使用不同 `qty` 组合，便于观察装托后扣减和移除效果。

### 3. 新增无码料包装中样例

- 额外新增 `1` 条 `包装中` 状态的无码料数据。
- 保持 `details: []`。
- 用于验证“直接输入装托数量”的无码料流程。

### 4. 数据风格要求

- 字段结构与现有 `tableData` 保持一致。
- `frameNo`、`orderNo`、`batchNo`、`furnaceNo`、`moldNo` 保持当前项目命名风格。
- 有码料明细继续使用长二维码编号格式，便于顺带验证超长字段显示。

## 风险与控制

- 风险：新增数据过多导致列表过长，影响手工测试效率。
- 控制：本次仅新增 `3` 条数据，保持最小可测集。

- 风险：新增数据字段不完整，导致页面逻辑异常。
- 控制：完全复用现有 `tableData` 字段结构，逐项补齐。

## 验证

- 切换到 `包装中` 页签后，能看到多条测试数据。
- 至少有 `2` 条有码料 `包装中` 数据可展开并勾选短支。
- 至少有 `2` 条无码料 `包装中` 数据可直接测试输入数量装托。
- `npm run build` 通过。
