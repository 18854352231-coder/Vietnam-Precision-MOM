# 工作台“查看工艺文件”统一设计

## 背景

当前各工作台里的“查看工艺文件”交互不一致：

- 包装工作台使用统一的工艺文件弹窗，支持按工艺类型查看文件列表，并展示产品号、产品名称。
- 裁切工作台、熔铸工作台仍使用提示框占位。
- 锯切工作台、挤压工作台将“查看工艺文件”混在通用表单弹窗里，属于假查看流程。

这会导致用户在不同工作台点击同一个按钮时，看到完全不同的页面和行为，影响操作一致性。

## 目标

- 仅统一各工作台里的“查看工艺文件”按钮。
- 所有工作台点击后都打开与包装工作台一致的工艺文件弹窗。
- 有当前产品信息时，自动带入产品号和产品名称。
- 没有当前产品信息时，也允许空值打开弹窗。
- 不改系统管理中的工艺文件维护页面。

## 范围

### 纳入改造

- `src/views/extrusion/PackagingWorkbench.vue`
- `src/views/extrusion/CuttingWorkbench.vue`
- `src/views/extrusion/SawingWorkbench.vue`
- `src/views/extrusion/ExtrusionWorkbench.vue`
- `src/views/casting/MeltingWorkbench.vue`

### 不在本次范围

- `src/views/system/process-docs/ProcessFiles.vue`
- 工艺文件的数据源、筛选规则、查看 PDF 逻辑
- 包装工作台现有弹窗的视觉样式和交互结构

## 统一方案

采用包装工作台当前实现作为唯一标准，直接复用共享组件 `src/components/ProcessDocumentDialog.vue`。

### 统一交互

- 点击“查看工艺文件”后打开统一弹窗。
- 弹窗内保留现有文件类型切换、文件列表、查看 PDF 按钮。
- 不再使用 `ElMessageBox.alert(...)` 作为占位查看。
- 不再使用通用表单弹窗承载 `processDoc` 假表单。

### 统一入参

- 挤压类工作台传 `processType="extrusion"`：
  - 包装
  - 裁切
  - 锯切
  - 挤压
- 熔铸工作台传 `processType="casting"`。
- 有可用数据时传入：
  - `productNo`
  - `productName`
- 无可用数据时传空字符串，允许直接打开弹窗。

## 页面级改造设计

### 包装工作台

包装工作台已经使用 `ProcessDocumentDialog`，作为标准页面保留现状，不调整交互，仅作为其他页面的对齐基准。

### 裁切工作台

- 移除 `viewProcessDocument` 中的提示框实现。
- 新增与包装一致的弹窗状态和上下文状态。
- 接入 `ProcessDocumentDialog`。
- 从当前排程信息中读取产品名称；若已有产品号字段，也一并传入。

### 锯切工作台

- 保留底部“查看工艺文件”按钮入口，但不再走通用表单弹窗。
- 删除 `operationDefinitions` 中 `processDoc` 的假表单字段依赖。
- 删除打开时填充 `docName/docVersion/issueDept/docRemark` 的旧逻辑。
- 删除提交时“工艺文件已打开查看”的成功提示分支。
- 改为独立弹出 `ProcessDocumentDialog`。
- 从 `currentTask` 中提取产品号、产品名称。

### 挤压工作台

- 保留现有按钮入口，但不再走通用表单弹窗。
- 删除 `processDoc` 对应的假表单默认值逻辑。
- 删除提交时针对 `processDoc` 的提示逻辑。
- 改为独立弹出 `ProcessDocumentDialog`。
- 从 `currentTask` 中提取产品号、产品名称。

### 熔铸工作台

- 移除 `viewProcessDocument` 中的提示框实现。
- 接入 `ProcessDocumentDialog`。
- `processType` 固定为 `casting`。
- 从当前炉台或当前绑定排程中尽量提取产品名称；若拿不到则空值打开。

## 实现细节

### 共享组件复用策略

- 不新增新的工艺文件弹窗组件。
- 不复制包装工作台的弹窗代码到其他页面。
- 统一复用 `ProcessDocumentDialog.vue`，保证后续维护只改一处。

### 旧逻辑清理原则

- 如果页面当前通过 `alert`、提示消息、或通用表单实现“查看工艺文件”，则全部替换。
- 与 `processDoc` 相关但仅用于假查看的字段、默认值、提交提示一并删除。
- 不清理与其他业务操作相关的通用表单逻辑，避免影响完工、退料、报废等流程。

### 数据缺省策略

- `productNo`、`productName` 允许为空字符串。
- 弹窗是否可打开，不依赖当前排程是否存在。
- 但若页面已有当前产品上下文，优先带入，保证和包装工作台一致。

## 风险与控制

### 风险

- 锯切、挤压页面当前将 `processDoc` 放进通用操作定义里，替换时容易误伤其他操作。
- 不同页面产品字段命名可能不完全一致，可能导致部分页面只能带入产品名称。
- 熔铸页面当前上下文较弱，可能拿不到完整产品号。

### 控制措施

- 仅移除 `processDoc` 相关分支，不改其他操作定义和提交逻辑。
- 改造前按页面确认实际可取字段，能传则传，不能传则回退为空。
- 保持 `ProcessDocumentDialog` 本身不变，降低联动风险。

## 验证方案

对以下 5 个工作台逐页手工验证：

- 包装工作台
- 裁切工作台
- 锯切工作台
- 挤压工作台
- 熔铸工作台

验证点：

1. 点击“查看工艺文件”后都打开同款弹窗。
2. 包装、裁切、锯切、挤压打开的是 `extrusion` 工艺文件。
3. 熔铸打开的是 `casting` 工艺文件。
4. 有产品信息时，弹窗顶部显示产品号和产品名称。
5. 无产品信息时，弹窗也能正常打开，不报错。
6. 原有业务弹窗与流程不受影响。
7. 修改后的页面无新增脚本诊断错误。

## 结论

本次改造采用“复用包装工作台现有工艺文件弹窗”的方式，统一所有工作台的“查看工艺文件”入口，收敛掉提示框和假表单逻辑，以最低改动实现统一体验，并保留系统管理页作为独立的工艺文件维护入口。
