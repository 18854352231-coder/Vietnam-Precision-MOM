# 制程检验班长审核页签设计

## 背景

当前 [ProcessInspection.vue](file:///D:/越南MOM/MOM/src/views/quality/ipqc/ProcessInspection.vue) 仅支持各工序下的质检和查看，缺少统一的班长审核承接页面。用户要求在现有制程检验页面中，紧跟“预包装IPQC”后增加“班长审核”页签，用于集中处理已质检但未审核的记录。

## 目标

- 在制程检验顶部 Tabs 中增加“班长审核”页签
- 质检完成后，记录进入“待班长审核”状态，而不是直接完成
- 班长审核页签集中展示所有待审核记录，并保留工序信息用于区分来源
- 点击“审核”时弹出检测项目明细，班长可修改项目数值
- 提交审核后重新计算判定结果，审核流程结束，记录回到原工序列表并显示为“已完成”

## 非目标

- 不新增独立菜单页面
- 不拆分为新的 Vue 页面文件
- 不引入后端接口，仅在当前前端 Mock 数据中完成闭环
- 不增加驳回、退回重检等多分支审核流转

## 推荐方案

采用“原工序页签负责质检，新增班长审核页签负责集中审核”的双区分工方案。

- 原 5 个工序页签继续保留：
  - 挤压IPQC
  - 时效IPQC
  - 裁切上料IPQC
  - 裁切IPQC
  - 预包装IPQC
- 在预包装IPQC后新增：
  - 班长审核

该方案的优点是：

- 不破坏现有工序质检使用习惯
- 待审核记录有统一入口，便于班长集中处理
- 页面仍在一个单文件组件内，改造范围清晰

## 页面结构

### 顶部页签

在现有 Tabs 中增加一个名称为 `班长审核` 的页签。

### 原工序页签列表

原工序页签仍展示各自工序的检验记录，保留原有字段，并继续按 `process === activeTab` 过滤。

操作列规则调整为：

- `completionStatus = 未完成`
  - 显示 `质检`
- `completionStatus = 待班长审核`
  - 显示 `查看`
- `completionStatus = 已完成`
  - 显示 `查看`

这样可以避免原工序页签和班长审核页签同时承担审核职责。

### 班长审核页签列表

班长审核页签的数据来源为所有 `completionStatus = 待班长审核` 的记录。

列表建议包含以下字段：

- 质检单号
- 检验工序
- 批次号
- 产品名称
- 模具编号
- 线体名称
- 质检人
- 更新时间
- 检验结果
- 操作

操作列仅提供：

- `审核`

## 状态流转

### 完成状态 `completionStatus`

统一使用以下三态：

1. `未完成`
2. `待班长审核`
3. `已完成`

### 流转规则

- 新增检验记录并提交质检：
  - 写入检测结果
  - `completionStatus = 待班长审核`
- 对现有未完成记录执行质检并提交：
  - 同样进入 `待班长审核`
- 在班长审核页签提交审核：
  - `completionStatus = 已完成`
  - 写入班长审核信息

## 数据模型

### 记录主字段

在现有记录结构中新增以下字段：

- `leaderReviewer`
- `leaderReviewTime`
- `inspectionItems`

其中：

- `leaderReviewer` 表示审核班长
- `leaderReviewTime` 表示审核时间
- `inspectionItems` 用于存储质检后形成的检测项目明细，供班长审核回显和修改

### 检测项目明细

`inspectionItems` 结构沿用当前规则明细的核心字段，并补充实际测量值与判定：

- `item`
- `standard`
- `tolerance`
- `unit`
- `actualValue`
- `status`

质检提交时，需把当前弹窗中的规则明细保存到记录中，而不是仅在详情弹窗中临时生成随机值。

## 质检逻辑调整

在现有质检弹窗提交流程中：

- 保留原有产品规则加载方式
- 保留综合判定计算方式
- 提交时新增保存 `inspectionItems`
- 提交后不直接完成，而是进入 `待班长审核`

目标写回字段包括：

- `result`
- `inspector`
- `updateTime`
- `inspectionCount`
- `inspectionItems`
- `completionStatus = 待班长审核`

## 班长审核弹窗

### 弹窗用途

班长审核弹窗用于查看并修改该记录的检测项目数值，然后完成最终审核。

### 弹窗字段

基础信息区包含：

- 质检单号
- 检验工序
- 批次号
- 产品名称
- 质检结果

明细区包含：

- 检测项目
- 标准值
- 单位
- 实际测量值（可编辑）
- 单项判定（根据修改后数值自动更新）

底部操作：

- 取消
- 提交审核

### 提交流程

班长点击提交审核后：

1. 读取当前编辑后的检测项目明细
2. 重新计算每个项目的 `status`
3. 根据明细重新计算综合 `result`
4. 写回 `leaderReviewer`
5. 写回 `leaderReviewTime`
6. 写回更新后的 `inspectionItems`
7. 将 `completionStatus` 改为 `已完成`

## 详情展示

详情弹窗需要改为优先读取真实保存的 `inspectionItems`，不再用随机值临时拼装。

同时增加班长审核信息展示：

- 班长
- 审核时间

如果尚未审核，则显示 `-`。

## 错误处理

- 若记录不存在，提示“记录不存在或已被更新”
- 若记录没有 `inspectionItems`，不允许进入班长审核，提示“缺少检测项目数据”
- 若记录状态不是 `待班长审核`，不允许提交审核
- 若检测项目明细全部为空或无效，仍按当前综合判定逻辑进行校验

## 验证要点

- 工序页签下未完成记录点击质检后，状态是否进入 `待班长审核`
- 班长审核页签是否能正确聚合所有待审核记录
- 点击审核后是否能看到真实检测项目，而不是随机明细
- 班长修改项目数值后，单项判定和综合判定是否同步更新
- 审核提交后，记录是否从班长审核页签移出
- 审核提交后，原工序列表中记录是否显示为 `已完成`
- 详情弹窗是否展示审核后的真实项目数据和班长审核信息
