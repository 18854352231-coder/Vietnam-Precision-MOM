# 有码上料临时队列设计

## 背景
- 当前 `挤压工作台` 的“有码上料”在点击“确认上料”时，直接将 `scanRodNo` 写入正式的“铝棒队列”。
- 现需调整为：扫码时先在“上料弹窗”内实时累积到临时“上料队列”，点击“确认上料”后，再统一写入正式“铝棒队列”。

## 目标
- 在“上料弹窗”内，`有码上料` 模式下新增一个临时“上料队列”展示区。
- 队列内容显示扫码得到的二维码编号。
- 临时队列支持扫码实时累积。
- 点击“确认上料”后，将临时队列批量写入正式“铝棒队列”。
- 阻止重复扫码，同一二维码重复加入时提示：`该二维码已在上料队列中`。

## 非目标
- 不调整 `无码上料` 的现有交互和数据写入逻辑。
- 不新增后端接口或持久化存储。
- 不修改正式“铝棒队列”的列结构，只沿用当前 `rodNo` 作为二维码编号写入。

## 用户流程
1. 用户打开 `挤压工作台` 的“铝棒上料”弹窗。
2. 选择 `有码上料 (PDA)`。
3. 用户输入或扫码二维码编号。
4. 点击扫码附属按钮后，将二维码编号加入弹窗下方的临时“上料队列”。
5. 若二维码编号已存在于本次临时队列中，阻止重复添加，并提示：`该二维码已在上料队列中`。
6. 用户可连续扫码，临时队列实时累积。
7. 用户点击“确认上料”后，临时队列中的所有二维码编号批量写入正式“铝棒队列”。
8. 写入成功后，关闭弹窗并清空本次临时队列。

## 界面设计

### 上料弹窗
- 仅在 `feedingMode === 'coded'` 时显示临时“上料队列”。
- 保留现有“扫码编号”输入框和附属按钮。
- 在“扫码编号”输入框下方新增一个表格区域，标题可使用“上料队列”。

### 上料队列表格
- 建议字段：
  - `序号`
  - `二维码编号`
- 当前版本不强制加入“删除”按钮，以最小实现为主。

## 数据设计

### 新增前端临时状态
- 新增一个用于保存本次 `有码上料` 临时结果的数组，例如 `codedFeedingQueue`。
- 队列项最小结构：

```ts
{
  rodNo: string
}
```

### 与正式铝棒队列的关系
- 临时队列仅用于弹窗内预览与批量提交。
- 正式“铝棒队列”仍写入 `loadedRods`。
- 写入 `loadedRods` 时字段保持现有结构：

```ts
{
  rodNo: string,
  extrusionBatchNo: string,
  status: '待挤压',
  loadTime: string,
  extrusionTime: ''
}
```

## 交互规则

### 有码上料
- `scanRodNo` 为空时，不允许加入临时队列，并提示现有文案：`请扫码或输入铝棒编号`。
- 点击扫码附属按钮时，执行“加入临时上料队列”逻辑，而不是直接写入正式“铝棒队列”。
- 加入成功后：
  - 当前输入框清空，便于连续扫码。
  - 临时“上料队列”立即刷新。

### 重复二维码
- 仅检查本次临时“上料队列”内是否重复。
- 若重复，阻止添加，并提示：`该二维码已在上料队列中`。

### 确认上料
- `有码上料` 模式下：
  - 若临时“上料队列”为空，不允许确认，并提示用户先扫码。
  - 将临时队列中所有 `rodNo` 批量转写到 `loadedRods`。
  - 每条记录继承当前排程的 `extrusionBatchNo`，并使用当前时间作为 `loadTime`。
  - 提交成功后关闭弹窗，并清空临时队列和输入框。
- `无码上料` 模式下：保持原有逻辑不变。

### 关闭弹窗
- 关闭“上料弹窗”时，未确认提交的 `有码上料` 临时队列清空。
- 这样可以避免上一次未提交扫码数据遗留到下一次上料。

## 错误处理
- 未选择排程时，沿用现有上料入口保护，不额外新增判断。
- 空二维码编号：提示并阻止加入。
- 重复二维码：提示并阻止加入。
- 临时队列为空时点击确认：提示并阻止提交。

## 兼容性
- 不影响现有 `scheduleLoadedRodsMap` 的排程切换逻辑。
- 仅改变 `有码上料` 的弹窗内暂存行为，不影响最终写入后的数据结构。
- 与“剔料”“挤压”“退料”保持兼容，因为它们继续消费正式 `loadedRods`。

## 实现要点
- 在模板中为 `有码上料` 分支增加临时队列表格。
- 新增一个“添加到临时队列”的方法供扫码按钮使用。
- 调整 `submitFeeding()`：
  - `coded` 分支改为从临时队列批量写入 `loadedRods`
  - `uncoded` 分支保持不变
- 增加一个“重置有码上料临时状态”的方法，在提交成功和关闭弹窗时复用。

## 测试要点
- `有码上料` 扫码一次后，临时队列新增一条二维码编号。
- 连续扫码多次后，临时队列正确累积。
- 重复扫码同一编号时，出现提示：`该二维码已在上料队列中`，且不新增记录。
- 点击“确认上料”后，正式“铝棒队列”新增对应数量记录，`rodNo` 等于扫码二维码编号。
- 点击“取消”关闭弹窗后，重新打开时临时队列为空。
- `无码上料` 保持原有行为不变。
